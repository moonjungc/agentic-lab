# repo-grade — 저장소 AI-Ready 채점

이 저장소가 "agent가 일하기 좋은 상태"인지 100점 만점으로 채점한다. 5개 카테고리를 각각 조사한 뒤 아래 루브릭으로 점수를 매기고, 지정된 출력 형식으로 보고한다.

## 채점 절차

1. 저장소 루트의 CLAUDE.md, GOLDEN_RULES.md(또는 동등 문서), README, 각 하위 폴더의 `.agent-rules.md`류 문서를 모두 읽는다.
2. `package.json` 등에서 테스트/빌드 명령을 확인하고, 실제로 `npm test`(또는 해당 명령)를 실행해 통과 여부를 검증한다.
3. 문서에 적힌 파일 경로·명령·규칙이 현재 코드 상태와 실제로 일치하는지 대조한다 (문서만 읽고 끝내지 않는다).
4. 아래 루브릭에 따라 카테고리별 점수(0/10/20)를 매긴다.
5. 지정된 출력 형식으로 보고한다.

## 루브릭 (5개 카테고리 × 20점 = 100점)

### (A) 길 안내 — 진입점·핵심 파일 안내가 있는가

| 점수 | 기준 |
|---|---|
| 0점 | 진입점이나 핵심 파일을 안내하는 문서가 전혀 없다 |
| 10점 | 일부 안내는 있으나 불완전하거나(핵심 파일 누락) 찾기 어려운 곳에 있다 |
| 20점 | CLAUDE.md 등에서 진입점·핵심 파일·폴더 구조를 명확히 안내한다 |

### (B) 규칙 문서 품질 — CLAUDE.md가 간결(35줄 이내)하고 명령어·금지사항을 담는가

| 점수 | 기준 |
|---|---|
| 0점 | CLAUDE.md가 없거나, 있어도 명령어·금지사항이 없다 |
| 10점 | 명령어·금지사항은 있으나 35줄을 초과해 장황하거나 구조가 산만하다 |
| 20점 | 35줄 이내로 간결하며 명령어와 금지사항을 모두 명확히 담는다 |

### (C) 숨은 규칙 문서화 — Why·Gotcha가 기록되어 있는가

| 점수 | 기준 |
|---|---|
| 0점 | 코드만 봐서는 알 수 없는 이유(Why)나 함정(Gotcha)이 어디에도 기록되어 있지 않다 |
| 10점 | 일부 Why/Gotcha는 문서화되어 있으나 산발적이거나 오래되어 신뢰하기 어렵다 |
| 20점 | 비직관적인 결정·함정이 이유와 함께 명확히 문서화되어 있다 |

### (D) 검증 게이트 — 테스트가 존재하고 npm test로 확인 가능한가

| 점수 | 기준 |
|---|---|
| 0점 | 테스트가 없거나, 테스트 실행 명령이 없거나, 실행해도 실패한다 |
| 10점 | 테스트는 있으나 커버리지가 얕거나(핵심 로직 미검증) 일부만 통과한다 |
| 20점 | `npm test`(또는 동등 명령) 한 번으로 핵심 로직 검증이 가능하고 전부 통과한다 |

### (E) 신선도 — 문서가 최근 코드와 일치하는가

| 점수 | 기준 |
|---|---|
| 0점 | 문서가 가리키는 파일 경로·함수·규칙이 현재 코드와 다르거나 존재하지 않는다 |
| 10점 | 대체로 일치하나 일부 항목이 코드 변경을 따라가지 못했다 |
| 20점 | 문서의 모든 경로·명령·규칙이 현재 코드 상태와 정확히 일치한다 |

## 출력 형식

다음 순서로 출력한다.

1. **채점 표** — 컬럼: `카테고리 | 점수 | 근거 | 개선 제안`. 행은 A~E 다섯 개.
2. **총점** — `총점: N / 100` 형태로 한 줄.
3. **ROI 순 개선 3가지** — 적은 노력으로 큰 점수 상승이 기대되는 순서로 정확히 3개. 각 항목에 예상 소요와 기대 점수 상승을 함께 표기한다.
